# 安全、数据分类与存储策略

本策略适用于 AG-UI 请求与事件、MCP 工具调用、ResultStore、Result API、前端执行日志和运行状态。

## 数据分类

| 级别 | 示例 | 允许进入模型/事件/日志 | 存储要求 |
|---|---|---|---|
| Public | 公开产品说明、公开统计口径 | 可以 | 常规完整性保护 |
| Internal | tenant/user/thread/run/toolCall 标识、工具名、计数 | 仅最小必要字段 | 访问控制、保留期限和审计 |
| Confidential | MCP 业务结果、客户资料、查询参数 | 不进入执行日志；进入模型前必须裁剪和脱敏 | ResultStore 加密、对象级授权、TTL、配额 |
| Restricted | 密钥、Token、密码、身份证、手机号、受监管原文 | 禁止进入模型事件和应用日志 | 不应保存；不可避免时使用专用密钥和更短 TTL |

`SensitiveTextSanitizer` 是进入模型 Observation 和可公开摘要前的最低脱敏基线。业务接入方必须按字段语义继续屏蔽账号、地址、医疗、财务及租户自定义敏感字段。禁止把原始 Tool Result、`resultJson`、`structuredContent`、工具参数或认证 Header 写入 AG-UI 事件与前端日志。

## ResultStore

- 每条记录不可变地保存 `tenantId/userId/threadId/runId/toolCallId`、工具身份、创建时间、过期时间和估算字节数。
- 每次读取和删除先校验可信 `AccessSubject` 与完整 run 归属，再判断过期；请求体、`forwardedProps` 和模型输出不得参与身份判断，未授权调用者不能借 404/410 差异探测对象状态。
- 本地 `InMemoryResultStore` 强制 TTL、全局条目容量、租户条目配额、单结果字节上限和租户字节配额。
- 达到租户配额或单结果上限时拒绝写入，不通过静默截断改变业务结果。达到全局条目容量时仅淘汰最早记录。
- 分布式实现必须原子执行引用唯一性、TTL、对象归属和租户配额检查，并实现 `SharedResultStore`。

## Result API

- 仅接受可信认证层解析出的主体；入口网关必须先删除外部同名身份 Header，再注入已认证身份。
- 返回码：未认证 `401`、无权访问 `403`、不存在 `404`、已过期 `410`、超限 `429`；不得将授权失败误报为成功或返回部分数据。
- 所有响应设置 `Cache-Control: private, no-store, max-age=0`、`Pragma: no-cache` 和 `X-Content-Type-Options: nosniff`。
- 应用层按 tenant/user 固定窗口限流；生产网关还应实施跨副本全局限流和请求体/URL 长度限制。

## 审计

审计记录只包含时间、访问结果、HTTP 状态和 tenant/user/thread/run/resultRef 关联标识，不包含结果正文。默认日志审计器在写日志前对所有标识做 SHA-256 截断哈希，避免日志成为业务数据副本。生产环境可替换 `ResultAccessAuditor`，将完整关联标识写入访问受控、不可篡改且有独立保留期的审计系统。

必须审计：读取成功、越权、未找到、过期、无效请求、限流和存储故障。告警至少覆盖连续越权、跨租户枚举、配额耗尽和 ResultStore 不可用。

## 并发与分布式部署

- AG-UI run 的隔离键为 `tenantId/userId/threadId/runId`；相同 thread 的并发 run 不共享 replay 流。
- 单副本默认使用 `InMemoryResultStore`、`AgUiEventStream`，AgentScope 默认使用 `InMemoryAgentStateStore`。
- 设置 `ac.deployment.distributed=true` 后，应用只接受实现 `SharedResultStore` 与 `SharedAgUiRunStateStore` 的 Bean；SAA 还要求 `SharedCheckpointSaver`，AgentScope 还要求 `SharedAgentStateStore`。缺少任一共享实现时启动失败，禁止带着进程内状态进入多副本环境。
- 共享 run store 必须同时提供事件持久化、Last-Event-ID replay、跨副本实时投递和相同 run 请求的原子幂等声明。

## 默认保留与清理

Result 默认 TTL 为 45 分钟，AG-UI 已结束 run 的 replay 默认保留 30 分钟。业务只能缩短 Restricted/Confidential 数据的期限；延长前必须完成数据影响评估。过期读取返回 `410`，随后记录从本地存储清理。
