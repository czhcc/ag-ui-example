# 模块间关系描述

本文汇总可移植 Rich UI 架构中各新增模块的职责、编译依赖、运行链路和边界约束。详细设计与任务完成情况参见[《可移植方案》](可移植方案.md)。

## 1. 总体结构

当前工程形成了“公共底座、适配与传输层、两条 Runtime 分支、独立 MCP 服务、统一前端 SDK”的结构：

1. `mcp-contract`、`rich-ui-core` 构成与 Agent Runtime 无关的公共底座。
2. `rich-ui-mcp-adapter`、`ag-ui-protocol`、`ag-ui-spring-web` 分别负责 MCP 结果解析、AG-UI 协议转换和 Web/SSE 传输。
3. `runtime-saa-adapter` 和 `runtime-agentscope-v2` 分别适配 Spring AI Alibaba 与 AgentScope v2 Java。
4. `agent-client` 和 `agentscope-client` 是两套 Runtime 的应用组装入口。
5. `mcp-server` 是独立的 MCP 工具服务。
6. `packages/agent-ui` 提供可复用的前端 SDK，`frontend` 是使用该 SDK 的应用壳。

公共模块禁止依赖 Spring AI Alibaba 或 AgentScope。Runtime 差异被限制在各自的 Adapter 和应用组装层内。

## 2. Maven 编译依赖

以下箭头表示“左侧模块依赖右侧模块”，仅列出工程内模块之间的直接依赖：

```text
mcp-contract

rich-ui-core
    └── mcp-contract

rich-ui-mcp-adapter
    └── rich-ui-core

ag-ui-protocol
    └── rich-ui-core

ag-ui-spring-web
    ├── ag-ui-protocol
    └── rich-ui-core

runtime-saa-adapter
    └── rich-ui-core

runtime-agentscope-v2
    ├── rich-ui-core
    ├── rich-ui-mcp-adapter
    └── ag-ui-protocol

agent-client
    ├── mcp-contract
    ├── rich-ui-core
    ├── rich-ui-mcp-adapter
    ├── runtime-saa-adapter
    └── ag-ui-spring-web

agentscope-client
    ├── mcp-contract
    ├── rich-ui-core
    ├── rich-ui-mcp-adapter
    ├── runtime-agentscope-v2
    └── ag-ui-spring-web
```

### 2.1 模块职责

| 模块 | 定位 | 主要关系与边界 |
| --- | --- | --- |
| `mcp-contract` | Rich Result 契约层 | 定义 DTO、枚举和 JSON Schema；不依赖 Runtime、Web 或存储实现 |
| `rich-ui-core` | 公共业务核心 | 提供 `RunScope`、ResultStore、Observation、Presentation 和 RuntimeEvent 等公共能力；只依赖契约层 |
| `rich-ui-mcp-adapter` | MCP 结果适配层 | 将 MCP SDK 返回值统一解析为公共 Rich Result，处理 `structuredContent`、文本降级和 `isError` |
| `ag-ui-protocol` | AG-UI 协议层 | 将内部 RuntimeEvent 转换为正式 AG-UI Event，维护消息、工具调用和终态关联 |
| `ag-ui-spring-web` | Web 传输层 | 提供 `/api/agent`、标准 SSE、事件重放、取消、能力声明和结果查询等接口 |
| `runtime-saa-adapter` | SAA Runtime 适配层 | 封装 Spring AI Alibaba Agent、工具拦截、事件映射、Checkpoint、取消和 HITL |
| `runtime-agentscope-v2` | AgentScope Runtime 适配层 | 封装 AgentScope v2 Java Agent、MCP Tool、中间件、上下文和事件映射 |
| `agent-client` | SAA 应用组装层 | 组装 SAA Runtime、MCP、公共 Rich UI 能力和 AG-UI Web |
| `agentscope-client` | AgentScope 应用组装层 | 组装 AgentScope Runtime、MCP、公共 Rich UI 能力和 AG-UI Web，不依赖 SAA |
| `mcp-server` | 独立 MCP 工具服务 | 对外提供工具及 Rich Result JSON，不依赖两个客户端或 Runtime Adapter |

`mcp-server` 当前没有直接 Maven 依赖 `mcp-contract`，而是按照 `mcp-contract` 中的 JSON Schema 生成兼容结果。因此两者是协议一致关系，而不是 Java 代码依赖关系。

## 3. Runtime 分支关系

两条 Runtime 分支相互独立：

```text
Spring AI Alibaba 分支
agent-client
    └── runtime-saa-adapter
            └── Spring AI Alibaba ReactAgent / Graph

AgentScope 分支
agentscope-client
    └── runtime-agentscope-v2
            └── AgentScope v2 Java
```

两条分支允许存在以下差异：

- Agent 生命周期和原生事件类型；
- Memory、Checkpoint 和 Agent State 的实现；
- HITL、中断与恢复机制；
- MCP Tool 和本地 Tool 的注册方式。

但经过 Adapter 后必须形成统一的公共语义：

- 相同的 `RunScope` 和访问控制规则；
- 相同的 MCP Rich Result 契约；
- 相同的 Observation、ResultReference 和 SurfaceSpec；
- 相同的 RuntimeEvent 和最终 AG-UI 事件语义。

因此，更换 Runtime 不需要修改公共 Rich UI 协议、AG-UI Web 层或前端渲染逻辑。

## 4. 完整运行链路

一次完整请求的主要链路如下：

```text
frontend
  → @ac/agent-ui
  → POST /api/agent
  → ag-ui-spring-web
  → agent-client 或 agentscope-client
  → 对应的 Runtime Adapter
  → MCP Client
  → mcp-server
  → Rich MCP Result
  → rich-ui-mcp-adapter
  → rich-ui-core
      ├── ResultStore
      ├── Observation
      └── Presentation / SurfaceSpec
  → ag-ui-protocol
  → ag-ui-spring-web 标准 SSE
  → @ac/agent-ui 状态归并和 Renderer
  → 页面渲染
```

`ag-ui-spring-web` 本身不选择具体 Runtime。`agent-client` 或 `agentscope-client` 在应用启动时向它注入对应的 `AgUiRunHandler`，从而让同一套 Web 和 AG-UI 传输能力服务不同 Runtime。

对于 Rich UI 数据，AG-UI 流中主要传递 `ui.surface.create/update/remove` 自定义事件、组件描述和 ResultReference；完整业务数据保存在 ResultStore 中，由前端通过结果接口按需读取。

## 5. 前端模块关系

```text
frontend
    └── @ac/agent-ui（packages/agent-ui）
            ├── RunAgentInput 构造
            ├── SSE 解析
            ├── AG-UI 事件状态归并
            ├── ResultReference 数据读取
            ├── 安全降级处理
            └── Chart、Table、Timeline、RelationGraph Renderer
```

`packages/agent-ui` 是可复用 SDK，`frontend` 是演示和集成应用。前端通过 `AGENT_BACKEND_URL` 切换后端：

- Spring AI Alibaba：默认 `http://localhost:8080`；
- AgentScope：默认 `http://localhost:8082`。

两种后端使用相同的 RunAgentInput、AG-UI SSE 事件和 Rich UI Profile，因此不需要维护两套前端组件。

## 6. 存储关系

各类状态由不同层负责，避免把 Runtime 状态、传输状态和业务结果混在一起：

| 状态类型 | 负责模块或 SPI | 作用 |
| --- | --- | --- |
| Rich Result 数据 | `rich-ui-core` 的 ResultStore | 保存完整工具结果，按 ResultReference 和访问主体读取 |
| AG-UI 事件流 | `ag-ui-spring-web` 的 RunStateStore | 负责事件序号、幂等、重放、实时投递和保留窗口 |
| SAA Memory/Checkpoint | `runtime-saa-adapter` | 保存 SAA Graph 执行状态和中断恢复信息 |
| AgentScope Agent State | `runtime-agentscope-v2` | 保存 AgentScope 会话和 Agent 状态 |

当前工程提供进程内实现及共享存储 SPI。生产多副本部署开启 `ac.deployment.distributed=true` 后，会拒绝使用进程内状态实现。Redis 或数据库等共享实现需要保证跨副本原子幂等、TTL、配额、事件重放和实时投递。

## 7. 安全与并发边界

`tenantId`、`userId`、`threadId`、`runId` 和 `toolCallId` 构成贯穿各模块的上下文：

```text
受信 Web 入口
  → AgUiRunHandler
  → Runtime Adapter
  → Tool 调用
  → ResultStore / RunStateStore
  → 结果读取与事件重放
```

主要约束如下：

- tenant 和 user 只能由受信入口根据认证信息建立，不能由请求正文覆盖；
- ResultStore 的保存和读取显式携带 `RunScope` 或 `AccessSubject`；
- AG-UI 事件流按 tenant、user、thread 和 run 隔离；
- Runtime Adapter 不使用全局 multicast EventBus 或隐式 ThreadLocal 承载用户运行上下文；
- 前端传入的 tools、context 和 forwardedProps 均经过校验、限制和脱敏；
- 日志和审计默认只记录必要元数据，不记录完整提示词、工具参数或敏感结果。

## 8. 依赖方向总结

整个架构遵循以下单向依赖原则：

```text
应用组装层
    ↓
Runtime Adapter / Web Adapter
    ↓
协议适配层
    ↓
公共核心层
    ↓
契约层
```

反向依赖被禁止：

- `mcp-contract` 和 `rich-ui-core` 不感知 SAA、AgentScope 或具体前端；
- `ag-ui-protocol` 不依赖 Spring Web 或具体 Runtime；
- `ag-ui-spring-web` 不直接依赖 SAA 或 AgentScope；
- `runtime-saa-adapter` 不依赖 AgentScope；
- `runtime-agentscope-v2` 和 `agentscope-client` 不依赖 Spring AI Alibaba；
- `mcp-server` 不依赖客户端应用；
- 前端只依赖 AG-UI 和 Rich UI 契约，不依赖后端 Runtime 的原生事件。

这种关系使公共 Rich UI 能力能够在不同 Java Agent Runtime 之间复用，同时把框架升级、运行状态和应用组装的影响限制在对应模块内。
